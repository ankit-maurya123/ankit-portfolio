The way I work

How I work

Simple rules I follow on every project — at work and on my own.

Clean code first

I write in MVC, use short files, name things properly. Six months later, I can still open the file and know what it does.

Ship fast, fix fast

I don’t sit on a task for a week. I push a first version, get feedback, and fix in the next round. Small steps.

Ask if I don’t know

No fake “yes I know”. If a task is new for me, I say so, then I read docs, try, and come back with a working demo.

Mobile is not optional

Every page I build is checked on my phone first. If it breaks on mobile, it’s not done yet.

Easy to work with

I talk to the designer, the client, the marketing person — whoever needs the thing. Short messages, clear updates.

Always learning

I moved from raw PHP to CodeIgniter 4, and now I’m moving to React and Node. I don’t stop.

Let’s talk

Hiring, freelance, or just a chat about React vs PHP — my inbox is open. I usually reply the same day.
